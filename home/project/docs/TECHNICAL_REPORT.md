## 1. Инфраструктура и Безопасность

### 1.1. Serverless-архитектура
Система Bio Hub Pro построена на базе экосистемы **Google Cloud Platform (Firebase)**, что обеспечивает практически неограниченную масштабируемость и высокую доступность.
- **Backend-инфраструктура**: Использование **Google Cloud Functions (Node.js)** для тяжелых вычислений (анализ RET-Reflex, гематологический скоринг), что позволяет изолировать бизнес-логику от клиентской части.
- **Real-time Sync**: Синхронизация данных через **Cloud Firestore**, обеспечивающая мгновенное обновление дашборда при поступлении данных из носимых устройств.

### 1.2. Протоколы шифрования и защиты данных
- **AES-256-GCM**: Применяется для шифрования персональных переписок в чатах. Ключи генерируются на стороне клиента (Client-Side Encryption), что исключает доступ провайдера к содержимому сообщений.
- **SHA-256**: Используется для хеширования и верификации целостности медицинских документов (анализов). Каждый загруженный файл получает уникальный цифровой отпечаток.
- **At-Rest & In-Transit**: Все данные в базе зашифрованы по стандарту AES-256, передача осуществляется исключительно по протоколу TLS 1.3.

### 1.3. Авторизация и мобильная защита
- **Firebase Auth + JWT**: Двухфакторная аутентификация через токены с коротким временем жизни.
- **Android Native (TWA) Integration**: Использование биометрической защиты (Fingerprint/FaceID) через нативный контейнер Android для разблокировки приложения.

## 2. Гематологический двигатель (Core Logic)

Ядром системы является двухэтапный алгоритм анализа общего анализа крови (ОАК).

### Этап 1: Дифференциальная диагностика анемий
Используется при обнаружении микроцитарной анемии для разделения ЖДА и Талассемии:
1.  **Mentzer Index**: $MCV / RBC$. Порог < 13 указывает на Талассемию.
2.  **Ehsani Index**: $MCV - (10 \times RBC)$. Порог < 15 указывает на Талассемию.
3.  **Shine & Lal**: $(MCV^2 \times MCH) / 100$. Порог < 1530 указывает на Талассемию.
4.  **England & Fraser**: $MCV - RBC - (5 \times Hb) - 3.4$. Значение < 0 указывает на Талассемию.

### Этап 2: Продвинутый RET-Reflex (Система автоматического прогнозирования)
При интеграции с анализаторами Sysmex или аналогичными, система обрабатывает ретикулоцитарные параметры:
- **MicroR & Hypo-He**: Оценка доли микроцитарных и гипохромных эритроцитов для выявления раннего дефицита железа (даже при нормальном Hb).
- **IRF (Immature Reticulocyte Fraction)**: Маркер активности костного мозга.
- **NRBC (Nucleated RBC)**: Автоматический флаг критических состояний.
- **RDW-SD**: Точная оценка анизоцитоза.

### RBC Score и SAO (Smart Outcome)
- **RBC Score**: Интегральный показатель здоровья эритроцитов, рассчитываемый нейросетью.
- **SAO**: Прогноз восстановления уровня гемоглобина на основе текущей терапии и динамики ретикулоцитов.

## 3. Функциональные модули

### 3.1. Умная Нутрициология и Vision AI
- **Vision AI (Gemini 2.5 Flash)**: Мультимодальный анализ фотографий блюд. Система распознает ингредиенты, оценивает объем порции и рассчитывает КБЖУ с точностью до 92-95%.
- **Voice Engine**: Интеграция Web Speech API для диктовки состава еды или симптомов, что критично для мобильного использования "на ходу".

### 3.2. Водный баланс и Fasting
- **Динамический расчет воды**: Формула $(Вес \times 35 мл) + коррекция$ на активность и кофеин.
- **Fasting Timer**: Умный таймер (16:8, 18:6), который автоматически корректирует окно питания, если пользователь зафиксировал высокую физическую нагрузку.

### 3.3. Медицинский блок
- **OCR Lab Scanner**: Технология оптического распознавания медицинских бланков. Извлекает маркеры, даже если они написаны от руки или имеют нестандартные единицы измерения.
- **БАД-контроль**: Проверка совместимости препаратов. Например, система даст сигнал, если пользователь принимает Железо одновременно с кофе или молочными продуктами (блокаторы всасывания).

## 4. AI-интеграция: AI-Advisor

### Механика корреляции
ИИ-советник не просто анализирует цифры, а строит связи:
- *Анализы (Низкий Ферритин) + Питание (Мало красного мяса) + Симптомы (Усталость) = Рекомендация по коррекции рациона и посещению гематолога.*

### Структура JSON-ответов ИИ
```json
{
  "summary": "Краткое описание состояния здоровья на текущий момент",
  "feedback": "Оценка выполнения целей за день (шаги, КБЖУ)",
  "recommendations": [
    "Персональный совет по питанию",
    "Совет по активности на завтра"
  ],
  "doctor_note": "Критическое замечание для лечащего врача (если применимо)"
}
```

## 5. Техническая спецификация данных

### 5.1. Схема данных Firestore
- **`users`**: Профили, антропометрия, `sharedWith` (права доступа для врачей).
- **`dailyLogs`**: Ежедневные записи (вода, вес, шаги, сон, настроение).
- **`labResults`**: Массив структурированных данных анализов с интерпретацией.
- **`appointments`**: Система бронирования времени у специалистов.

### 5.2. Требования к разработке
- **TypeScript Strict Mode**: Обязательное использование типизации для всех сущностей `User`, `LabResult`, `Meal`.
- **PWA / Service Workers**: Обеспечение базовой работоспособности (просмотр логов, чтение рекомендаций) в условиях отсутствия интернета (Offline-first).
